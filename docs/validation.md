# Validation Evidence — V1.0

Validation question: **Does the application meet the intended user need?**

Representative scenario:
1. Staff creates a consultation slot.
2. Student selects the slot and books it.
3. Student sees the confirmed booking.
4. Student cancels their own booking.

Success criterion: a representative user can complete the booking and cancellation flow without developer intervention and receives clear feedback when an invalid action is attempted.

Evidence to collect during the live demonstration:
- successful booking flow
- rejected overlapping booking
- successful own-booking cancellation
- rejected attempt to cancel another student's booking
